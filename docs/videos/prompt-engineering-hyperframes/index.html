Spring AI / 提示词工程

提示词工程
不是魔法

它是把目标、格式、上下文和生成边界说清楚的一套方法。

核心模型

两层：怎么说 与 怎么生成

提示词文本负责表达任务，ChatOptions 负责调节模型生成方式。

Spring AI 调用骨架

chatClient.prompt() .system("规则") .user("任务 + 上下文") .options(ChatOptions.builder() .temperature(0.2) .maxTokens(120) .build()) .call().content();

基础模式

先掌握 5 个基础问法

零样本 Zero-shot不给例子，直接下指令。
少样本 Few-shot给例子，让模型照格式做。
系统提示 System设定本次请求或对话规则。
角色提示 Role让模型带着稳定视角回答。
上下文 Context补充背景，让回答贴合场景。

推理模式

复杂任务要引导推理

不是只让模型回答，而是让它先拿原则、分步骤、多采样、再比较路径。

  • 回退提问 Step-back：先问高层原则，再回到具体任务。
  • 思维链 CoT：一步步推理，减少跳步。
  • 自洽性 Self-consistency：多跑几条推理路径，再投票。
  • 思维树 ToT：分叉、评估、剪枝、继续展开。

思维树 Tree of Thoughts

真正的树：每一层都可以继续分叉

A. 先读文档信息全，但反馈慢
B. 先跑 Demo最快看到结果，继续展开
C. 先改 Prompt有趣，但容易没上下文
B1. 跑完整 main覆盖多，但耗时更长
B2. 最小 ChatClient 调用最适合新手马上执行
B3. 跑 Web 示例直观，但依赖更多

自动提示词工程 APE

让模型帮你改提示词

先生成多个候选提示词，再按格式约束、清晰度、减少歧义来评估。

候选提示词评估

  • 只能输出 POSITIVE / NEGATIVE / NEUTRAL
  • 角色清楚：情感分类器
  • 约束明确：不要额外解释

代码提示

代码提示要写清规格

语言、输入、输出、边界情况都要说清楚。别让模型猜你想要什么。

用 Python 写一个函数： 输入整数列表，返回平均值； 如果列表为空，抛出 ValueError。 def average(nums): if not nums: raise ValueError("nums不能为空") return sum(nums) / len(nums)

选择模式

不是背 11 个名字，而是看清任务

格式明确

用零样本、少样本、系统提示控制输出。

场景明确

用角色提示和上下文提示，让回答贴合读者与背景。

推理复杂

用回退提问、思维链、自洽性、思维树引导思考。
